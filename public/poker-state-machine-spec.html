TECHNICAL ARCHITECTURE SPECIFICATION

多人德州扑克状态机完整运行规范

本文档完整呈现当前多人联机德州扑克底层状态机的完整运作机制、数学逻辑、事件流向与网络时序，并系统阐述为支撑《三国杀》《风声》式卡牌技能体系而升级的生命周期钩子（Lifecycle Hooks）与卡牌池安全管理器（CardPoolManager）架构。

1. 系统架构与分层总览

RiverLab 采用服务端权威（Server-Authoritative）的单向数据流架构。客户端（Web 前端）只负责展示与发送玩家意向动作，所有的随机数洗牌、加注合法性校验、轮次流转、筹码池结算均在服务器核心状态机中完成。

房间协调层 (MultiplayerRoom) Manager

管理 8 个固定座位和观战者列表，维护物理连接（Connected）、准备就绪状态（isReady）、房主权限（isHost）、AI 补位，以及驱动倒计时器与超时强弃。

规则核心 (Poker Engine & StateMachine) Reducer

纯函数式状态机。维护当前庄位（Button）、活跃行动位（ActiveIndex）、街区（Street）、主池与边池、加注上限与下限。确保筹码守恒与发牌随机种子（Seed）可复现。

信息脱敏广播 (Fog of War) Security

广播状态时，按客户端 ID 执行独立序列化。玩家只能收到自己的 2 张底牌，他人底牌在未到摊牌前在 JSON 中被强制置空，杜绝前端抓包作弊。

1. 大厅与就绪验证 (Lobby & Ready) Phase 1

前置条件：在座玩家满足 4 ≤ count ≤ 8，且所有非房主玩家均已点击“准备就绪”。

状态变迁：房主点击“开始游戏”，房间状态由 status = "lobby" 迁入 status = "playing"，生成首手待命标记 firstHandPending = true。

2. 定庄与洗牌 (Button & Shuffle) Phase 2

庄位轮转：buttonIndex = findNextOccupied(state, buttonIndex)。跳过空座和筹码为 0 的玩家，严格顺时针移庄。

可复现牌堆：利用 SeededRng(seed).shuffle() 生成包含 52 张唯一点数花色的牌堆 deck，重置 deckIndex = 0。

3. 盲注扣除 (Blinds Posting) Phase 3

盲注位置规则：多人桌（3-8 人）由 Button 顺时针下一位下小盲（SB），下下位下大盲（BB）；双人单挑（Heads-Up）中，Button 下小盲并先行行动，对手下大盲。

筹码扣减：通过 contribute() 扣减玩家筹码，记入 committedStreet 与 committedHand，生成下注记录日志。

4. 底牌分发 (Dealing Hole Cards) Phase 4

物理次序分发：从小盲（SB）位开始，顺时针每位活跃玩家各发 1 张，连续分发 2 轮，每人获得 2 张底牌，deckIndex 累加 activeCount * 2。

防作弊加密：生成客户端状态时，仅 Hero 座位可获知自己的 holeCards，其余座位下发空数组。

5. 翻前下注轮 (Preflop Betting) Phase 5

先行者定义：翻前由大盲（BB）顺时针下一位（UTG 枪口位）先行决策（单挑时由 Button 先行）。

初始标尺：currentBet = bigBlind，minRaise = bigBlind。行动者可选择 Fold、Call (BB)、或 Raise (至 ≥ 2BB)。

6. 翻牌与转牌 (Flop & Turn) Phase 6

轮次重置：各玩家 committedStreet = 0，currentBet = 0，minRaise = bigBlind。

销牌与发牌：销 1 张暗牌（burn），翻牌圈发 3 张公共牌；转牌圈销 1 张，发 1 张公共牌。由 Button 顺时针首位存活玩家先行行动。

7. 河牌终局轮 (River Round) Phase 7

最后发牌：销 1 张，翻开第 5 张公共牌（河牌）。这是牌局最后一次下注机会。

下注闭合：当所有活跃且未全压玩家均行动且当前街区投入筹码一致（或仅剩 1 人未弃牌），进入摊牌。

8. 摊牌与牌力比对 (Showdown) Phase 8

7 选 5 最佳牌力：调用 evaluateSeven([...holeCards, ...community]) 计算 21 种组合中最大的 5 张牌得分。

亮牌次序：河牌圈最后一名激进加注者（Aggressor）先亮牌，若平跟则按顺时针依次亮牌。

9. 分池与结算 (Settlement & Next Hand) Phase 9

主池与边池：按贡献筹码阶梯计算各池胜者。单手结算完成后状态迁入 complete。

下一手流转：游戏进入待机并展示战报，由房主点击“开始下一手”（nextHand()）推进到下一轮。

3. 核心规则、算法与数学约束

3.1 合法动作计算器 (`getLegalActions`)

对于任意活跃玩家，状态机依据其个人筹码 seat.stack、本轮已投入筹码 seat.committedStreet、牌桌当前下注额 currentBet 以及最小加注量 minRaise 实时计算出 6 项合法操作分支：

动作类型 合法性触发条件 (Boolean Guard) 筹码计算与目标要求
Fold (弃牌) toCall > 0 放弃当前手牌并退出本局争夺，不退还已投入筹码。
Check (看牌) toCall === 0 本轮前面无人下注（或自己在 BB 且没人加注），过牌给下一位。
Call (跟注) toCall > 0 && seat.stack > 0 跟注额 callAmount = Math.min(toCall, seat.stack)。若筹码不足则进入 All-in。
Bet (下注) currentBet === 0 && maxTo > 0 最小下注为 bigBlind（除非自身筹码不足 1BB 被迫 All-in）。
Raise (加注) currentBet > 0 && !raiseLocked && maxTo > currentBet 加注目标必须满足 target ≥ currentBet + minRaise（除非 All-in）。
All-in (全压) seat.stack > 0 && (!raiseLocked || maxTo <= currentBet) 投入全部剩余筹码，将 seat.allIn = true，不再参与后续街道下注。
⚠️ 未足额全压与加注权锁定 (Under-raise & Raise Lock)
当有玩家 All-in 但其加注额小于标准 minRaise 时（称为未足额加注），已经行动过的其他玩家的加注权不会被重新激活（raiseLocked = true）。这些玩家只能选择 Fold 或 Call，防止深筹码利用短码 All-in 进行二次再加注。

3.2 主池与多重边池算法 (Side Pot Calculation)

当一名或多名玩家 All-in 时，状态机会将总底池按投入筹码梯级切割为 1 个主池（Main Pot）和若干个边池（Side Pots）： 

function settleShowdown(state: FullGameState) {
  // 提取所有非 0 投注梯级并升序排序 (例如: [100, 300, 1000])
  const levels = [...new Set(state.seats.map(s => s.committedHand).filter(a => a > 0))].sort((a, b) => a - b);
  let previousLevel = 0;

  for (const level of levels) {
    // 凡是贡献额 ≥ level 的玩家，均向当前边池注入 (level - previousLevel) 的筹码
    const contributors = state.seats.filter(s => s.committedHand >= level);
    const potAmount = (level - previousLevel) * contributors.length;
    previousLevel = level;

    // 仅在参与了此梯级且未弃牌的玩家中比对牌力
    const eligible = contributors.filter(s => !s.folded);
    if (eligible.length === 0) continue;

    // 牌力最高者赢得该池；若平局则顺时针均分，奇数筹码从小盲位起顺时针补齐
    const bestScore = Math.max(...eligible.map(s => evaluateSeven([...s.holeCards, ...state.community])));
    /* 分发筹码... */
  }
}

4. 网络时序、计时器与断线保护

4.1 单次回合计时与延时卡机制

  • 常规思考时间：默认为 regularTurnSeconds = 20s。轮到某玩家时，服务器启动计时器并记录 turnExpiresAt = Date.now() + 20000。
  • 延时卡使用限制：仅当思考时间剩余 ≤ 5 秒 时方可激活，每次消耗 1 张延时卡，思考时间延长 regularTurnSeconds（即 20 秒），并实时重置计时器。
  • 超时强制弃牌 (Auto-Fold)：计时器归零时，无论当前是否可 Check，服务器权威触发 handleTimeout() 强制执行 fold，杜绝死锁与挂机。

4.2 离桌与断线异常处理

场景 状态机响应与处理机制
正值行动时断线/离桌 立即触发超时强弃（Auto-Fold），退还其本轮未跟注筹码，将当前行动权顺延给下一位存活玩家。
非行动轮次玩家离桌 将其座位标记为弃牌（folded = true）。若全场存活玩家仅剩 1 人，直接进入无争议胜（Uncontested Settle）。
房主退出房间 顺时针将房主身份（Host）自动移交给下一位在座的真人玩家（若无真人则移交给首位观战者）。
手牌中途仅剩 1 人 直接终止公共牌发牌，底池全额发放给唯一存活玩家（settleUncontested），跳过摊牌（Showdown）。

5. “胡闹德州”差距诊断（为什么原状态机不够？）

《三国杀》（出牌阶段、判定阶段、回合开始前技能）与《风声再临》（截获情报、调换手牌）这类桌游模式，其核心是“事件驱动与时机插桩机制”。经审计，原德州状态机存在以下 5 项根本性架构缺陷：

缺陷 1：缺乏细粒度阶段与时点挂钩 Gap 1

原 startHand 在一个同步调用内连续执行重置、洗牌、发底牌、盲注并直接移交 UTG；原 advanceAfterRound 在一瞬间销牌、发公共牌并移交下一个行动者。外部没有“发牌瞬间”或“回合开始判定”的暂停与响应窗口。

缺陷 2：合法动作硬编码，无法修饰 Gap 2

getLegalActions 写死了 canFold = toCall > 0。如果一个技能要求“封锁某玩家，使其翻牌圈不能弃牌”，旧系统只能硬改底层文件；没有动作修饰管线（Action Modifiers）来动态屏蔽或开放动作。

缺陷 3：牌堆单向消费，缺乏变造守恒 Gap 3

原牌堆是 deck[deckIndex++] 的递增数组。技能如“将底牌变成方块 3（若不在场上）”，若直接赋值，如果方块 3 已在公共牌或他人手中，就会出现重牌（双鬼牌），导致评估器崩溃或逻辑错误。必须有全局排他性检测与对调置换。

缺陷 4：单向动作契约，不支持多阶段互动 Gap 4

原有 WebSocket 协议仅支持 fold/check/call/bet/raise/all-in 6 种动作。技能发动通常伴随选择目标玩家、选择手牌、响应防御等子状态，原状态机与倒计时完全没有处理此类分支的能力。

缺陷 5：信息可见性权限固定 Gap 5

原 buildClientState 只有“自看”或“上帝视角看全场”两级。像“常驻技能：预视下一张翻开的公共牌”或“借看某一家手牌”，无法向指定玩家精准注入非公开数据。

6. 改进后的分层状态机与“胡闹德州”接入蓝图

我们在 lib/poker/state-machine.ts 中正式引入了细粒度状态机与拦截器架构。该架构完全向后兼容标准德州扑克（60 项单元测试 100% 满分通过），同时为“胡闹德州”技能模式提供了标准的即插即用挂载点。

6.1 核心状态机钩子体系 (`PokerLifecycleHooks`)

生命周期钩子函数 触发时机 (Trigger Timing) 胡闹德州技能应用范例
beforeHandStart(state) 洗牌前、座位准备时 触发“摸取武将技能牌”、“抽取本局被动锦囊”等。
afterHoleDealt(state) 2 张底牌发到每人手中后 先机技能：开局透视自身牌型强度，或决定是否重抽底牌。
beforeStreetDeal(state, street) 销牌与翻出公共牌前 观星技能：调换牌堆顶接下来两张牌的顺序。
afterStreetDeal(state, street) 公共牌翻开的一瞬间 “翻开河牌时，可选择与某一家交换底牌”。
onTurnStart(state, activeIndex) 轮到玩家行动开始（准备阶段） 回合开始时判定 Buff 是否到期；主动技能发动窗口。
filterLegalActions(state, id, legal) 计算合法动作时 “封锁目标使其翻牌圈不能弃牌”（强制 canFold = false）。
beforeAction(state, action) 玩家确认下注意图前 “下注时，将底牌变造成方块 3”；扣减技能能量。
beforeShowdown(state) 比牌前一刻（终局窗口） “反转手牌大小”、“偷取对手一张公共牌使用权”。
afterSettlement(state, result) 底池分发完成时 “摸鱼技能：每输一个池获得 100 补贴”；“连赢筹码加成”。

6.2 四大典型技能的实战接入方案

技能 A：河牌与某一家交换底牌 Card Swap

挂载点：afterStreetDeal 或 onTurnStart (当 street === "river")。
实现 API：直接调用 CardPoolManager.swapHoleCards(state, heroId, targetId)。
安全性保障：底层确保原子交换，自动校验两家是否存活，日志写入变迁记录，防止手牌丢失。

技能 B：将底牌变造成方块 3 Transform

挂载点：beforeAction (轮到自己决策时)。
实现 API：调用 CardPoolManager.transformCard(state, heroId, 0, { rank: 3, suit: "d" })。
安全性保障：首先通过 isCardInPlay() 扫描全场底牌、公共牌与已销牌堆。若方块 3 已在场则直接拦截并阻断技能；若不在场，则将目标牌与牌堆深处未发出的方块 3 进行对调，严格保持 52 张牌的总量守恒！

技能 C：常驻技能·预知下张公共牌 Foresight

挂载点：afterStreetDeal (由 Preflop / Flop / Turn 阶段更新)。
实现 API：调用 CardPoolManager.peekNextCommunityCard(state)。
安全性保障：纯读接口，不增加 deckIndex。在 buildClientState 中将预视的卡牌精准追加进该持有技能玩家的私有数据流中。

技能 D：翻牌圈使其不能弃牌 Disruption

挂载点：filterLegalActions 与 SeatModifier。
实现 API：为目标添加 sm.addSeatModifier(targetId, { cannotFold: true })。
安全性保障：在状态机计算动作时，将 canFold 置为 false；若强行发送弃牌消息，状态机会抛出异常拒绝非法弃牌，迫使其只能 Check、Call 或 All-in！
